# Kakuro AI Lab Implementation Plan

**Goal:** Build the offline academic CSP platform specified in `docs/specification.md`.

**Architecture:** Pure Python model and solver produce immutable JSON events; FastAPI streams events from a worker, React reconstructs state and keeps games locally. Proof checking enumerates premises independently. Generation edits a valid witness at disagreement cells and re-counts solutions.

**Stack:** Python 3.11, FastAPI, pydantic, React, Vite, Recharts.

**Design decision:** Local-only deployment matches the required offline operation. Ivory/ink/orange visual design with a persistent navigation rail and a central interactive board. User explicitly requested continuous execution, so no design approval gates.

## Constraints and review focus
No solver libraries in production. No synthetic measurements. Bounded runs distinguish incomplete from unsatisfiable/unique. Invalid shapes, stale game state, cancellation, exhausted generation budgets, and malformed proofs require explicit handling. Proof certificates establish local entailment, not unconditional correctness of guesses. Diagnosis minimality is reported only after exhaustive BFS at earlier depths.

## Final review and decisions
Four important findings reproduced and fixed: generated identity collisions, stale reveal results, completion undo locking, and uncertified state mutations. Added strict API digit validation, exact minimum-clue core, level-three unique reveals, across-direction filtering and a demonstration fixture with genuine Full CSP backtracking. No minor review findings were deferred.

Ruling: retain explicit provisional difficulty for sizes 7–12 instead of claiming unrun calibration; larger generation can exhaust caps. Cost: those research acceptance items remain open.

Ruling: minimum clue-cardinality is conditioned on fixed player entries; the joint entry/clue minimum is not claimed. Cost: a different minimality objective needs further work.

Ruling: stop browser automation after its Windows URL safety failure; retain passing DOM/API/build evidence without claiming visual QA. Cost: screenshots, mobile rendering and console walkthrough remain unverified.

## File responsibilities
`core/model.py`: structural invariants, run graph and validation.
`solver/constraints.py`: combinations and domain-compatible tuples.
`solver/engine.py`: search, heuristics, metrics and trace.
`solver/techniques.py`: ordered human deduction applications.
`solver/verifier.py`: independent certificate enumeration.
`solver/diagnose.py`: BFS deduction contradiction and assumption core.
`solver/replay.py`: snapshots and deterministic explanation text.
`generator/generate.py`: seeded layout/fill/repair and target attempts.
`generator/difficulty.py`: score and calibrated thresholds.
`main.py`: validated API and bounded threaded NDJSON stream.
Frontend components split board, playback, game state and research pages.
